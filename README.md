# Персональный сайт

Минималистичный сайт: короткий рассказ о себе, проекты и записи о том, как они создавались и обновлялись.
У одного проекта может быть сколько угодно записей — они собираются в хронологию на странице проекта.

**Стек:** [Hugo](https://gohugo.io) (статический генератор) + [Sveltia CMS](https://sveltiacms.app) (админка в `/admin`) +
GitHub Actions → VPS на Hetzner с [Caddy](https://caddyserver.com) (HTTPS автоматически).
На сервере нет базы данных и бэкенда — только статические файлы.

```
Админка /admin ──коммит──▶ GitHub ──push──▶ Actions: hugo --minify ──rsync──▶ VPS (Caddy)
```

## Как устроен контент

| Что | Где лежит | В админке |
|---|---|---|
| Проекты | `content/projects/<адрес>/index.md` + картинки рядом | Проекты |
| Записи | `content/posts/<адрес>/index.md` + картинки рядом | Записи |
| Имя, «обо мне», фото, ссылки, подвал, цвет, тема, светлая/тёмная | `data/site.yaml` | Настройки сайта |
| Общие картинки (фото и т. п.) | `assets/uploads/` | Ресурсы |

Запись привязывается к проектам полем `projects` (список адресов проектов). Страница проекта
сама находит все свои записи и показывает их хронологией; на странице записи — ссылки «раньше / позже» по проекту.

Записи пишутся в Markdown. Поддерживаются картинки (автоматически уменьшаются и переводятся в WebP;
картинка отдельным абзацем с title становится `<figure>` с подписью), подсветка кода
и формулы `\( … \)`, `\[ … \]`, `$$ … $$` — они рендерятся при сборке, без JavaScript в браузере.

## Темы оформления

Выбираются в админке: **Настройки сайта → Тема оформления**. Там же — **Светлая или тёмная**:
как в системе у посетителя, всегда светлая или всегда тёмная. Цвет акцента работает в любой теме.

| Тема | Файл | Характер |
|---|---|---|
| Базовая | `assets/css/themes/default.css` | системный шрифт, нейтральная бумага |
| Книжная | `assets/css/themes/book.css` | антиква Literata, тёплая бумага, курсивные подзаголовки |
| Моно | `assets/css/themes/mono.css` | всё моноширинным JetBrains Mono, статусы в скобках |
| Строгая | `assets/css/themes/strict.css` | гротеск Golos Text, чёрное на белом, крупный заголовок |

Тема — это токены (`--l-*` для светлого режима, `--d-*` для тёмного, шрифты, размеры) и пара своих правил;
разметка у всех тем общая. Шрифты лежат в `static/fonts/` (лицензия OFL), браузер скачивает только шрифт выбранной темы.

Новая тема: скопировать файл темы под новым именем, поменять токены и добавить вариант в поле `theme`
в `static/admin/config.yml`.

## Админка

Адрес: `https://<домен>/admin/`. Вход по личному токену GitHub — отдельный OAuth-сервер не нужен.

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token.
2. Repository access: **Only select repositories** → этот репозиторий.
3. Permissions → Repository permissions → **Contents: Read and write** (Metadata: Read-only добавится сама).
4. Скопировать токен и вставить в админке («Войти с помощью токена доступа»).

Каждое сохранение в админке — коммит в `main`; через ~1 минуту изменения на сайте.
Ход сборки виден во вкладке Actions репозитория.

Токен хранится только в браузере. Сама страница `/admin` публичная, но без токена с правом записи
в этот репозиторий ничего сделать нельзя.

Локально (в Chrome/Edge) можно работать без токена: `make dev`, открыть `http://localhost:1313/admin/`
→ «Работать с локальным репозиторием» → выбрать папку репозитория. Изменения пишутся прямо в файлы, коммит — вручную.

## Локальная разработка

Нужен Hugo **extended** той же версии, что в `.github/workflows/deploy.yml` (`HUGO_VERSION`).

```bash
make dev     # http://localhost:1313, с черновиками
make build   # сборка в public/
```

Шаблоны — в `layouts/` (без внешней темы), стили — `assets/css/main.css`.

## Деплой

### 1. Сервер (один раз)

Чистый VPS с Debian/Ubuntu, A-запись домена указывает на его IP.

```bash
# на своём компьютере: ключ, которым GitHub Actions будет заходить на сервер
ssh-keygen -t ed25519 -f ~/.ssh/site_deploy -C github-deploy -N ''

# скопировать папку deploy/ на сервер и запустить настройку от root
scp -r deploy root@<IP>:/root/site-deploy
ssh root@<IP> "bash /root/site-deploy/setup-server.sh <домен> '$(cat ~/.ssh/site_deploy.pub)'"
```

Скрипт ставит Caddy, создаёт пользователя `deploy` и кладёт `Caddyfile` с вашим доменом.
Если нужен и `www.<домен>` — у него тоже должна быть DNS-запись (он редиректит на основной домен).

### 2. Настройки репозитория

Settings → Secrets and variables → Actions:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `DEPLOY_HOST` | IP или домен сервера |
| Secret | `DEPLOY_USER` | `deploy` |
| Secret | `DEPLOY_SSH_KEY` | содержимое `~/.ssh/site_deploy` (приватный ключ) |
| Secret | `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -t ed25519 <IP>` |
| Variable | `SITE_URL` | `https://<домен>` |

Репозиторий для админки задан в `static/admin/config.yml` (`backend.repo`).

### Как выкладывается и как откатить

Каждая сборка — отдельная папка `/var/www/site/releases/<коммит>`; `current` — симлинк на активную,
переключение атомарное, хранятся 5 последних. Откат на сервере:

```bash
sudo -u deploy site-rollback            # на предыдущий релиз
sudo -u deploy site-rollback <релиз>    # на конкретный (список: ls /var/www/site/releases)
```

Следующий push выложит новый релиз как обычно.

## Обновления зависимостей

- **Hugo** — `HUGO_VERSION` в `.github/workflows/deploy.yml`.
- **Sveltia CMS** — версия в `static/admin/index.html` (зафиксирована, чтобы админка не менялась внезапно).
- **KaTeX** (стили формул) лежит в `static/katex/`; версия должна совпадать с той, что встроена в Hugo.
